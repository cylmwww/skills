# 项目残留清理

在用户指定目录内，通过用途、引用和运行状态判断可删项，先完成必要验证再删除。保留源码、构建输入、运行依赖、正式交付物及用户数据。

## 确定范围与基线

- 区分“只查看候选项”和“执行清理”。用户只要求盘点时输出候选清单；已授权清理时，完成验证后直接处理已确认项，不重复索取许可。含糊的查看请求不自动授权不可恢复的删除。
- 读取适用的 AGENTS.md、项目说明、忽略规则和构建入口。记录 Git 初始状态，保护原有改动；无 Git 时依靠文件清单和用途判断。
- 先列顶层目录，再对候选目录计算文件数、逻辑字节数、修改时间和代表性内容。避免为找少量临时文件反复遍历整个运行时或模型库。
- 最终使用精确目标清单；不把全盘、用户缓存目录或其他项目自动纳入范围。

## 判定每个候选项

为每项形成简短依据：路径、大小、用途、是否被 Git 跟踪、代码或构建引用、是否可重建、占用情况、删除或保留的结论。输出可按同类项目合并。

- 名称包含 `.tmp`、`cache`、`build`，被 Git 忽略，或修改时间较旧，都只用于发现候选项，不能证明可删。
- 用 `rg` 搜索精确目录名和相关路径构造，查看调用上下文。检查源码、测试、构建脚本、启动器和配置；必要时定向搜索被忽略的配置和本地说明，默认搜索未命中不代表没有依赖。
- 测试代码自行删除并重建的输出目录可作为候选；测试直接调用的临时 Python、工具链或其他环境仍是依赖。
- 区分打包输入与输出。模型权重、第三方源码、标签映射、下载包、锁文件、构建解释器可能仍是输入。确认 ZIP、安装器外壳等由脚本生成且正式交付文件保留后，才把它们作为中间产物。
- 安装验证副本可在确认独立、无唯一数据、无引用和占用后删除；不能仅因存在另一安装目录就认定两者可互换。
- 用户项目、影像、导出结果、验收日志、哈希清单和历史证据按有价值资料处理。可重跑并不代表可以丢弃唯一结果；用途不明的项目保留，并继续处理已经明确的项目。
- 不为了腾空间修改测试或构建代码，把当前依赖改成可删项。依赖治理属于另一个变更范围。

## 检查运行与占用

- 结合进程可执行路径、可获得的命令行、后台任务状态和必要的文件占用信息判断。不要输出可能含密钥的完整命令行。
- Windows 上可先用 `Get-CimInstance Win32_Process`；不可用时使用 `Get-Process` 的路径信息，但说明检查覆盖范围。可执行文件在项目外的解释器仍可能运行项目脚本；无匹配进程不等于无文件占用。
- 文件独占打开检查只能说明检查时刻的句柄情况，不能证明以后不会被重新读取。可变的运行目录需要确认任务结束，或留待任务结束后处理。
- 不终止用户进程来完成清理。删除前复核候选项状态；发现新写入、活动任务或占用时跳过受影响项。

## 删除前验证

按风险选择足以判断此次清理影响的检查，不把每次缓存清理扩展为完整验收：

1. 确认保留的源码、构建输入、运行时、资源和正式交付文件存在，候选项不是其中的依赖。
2. 清理安装副本、大型打包产物，或用户明确要求完整性验证时，优先使用已有逐文件清单与发布校验值。核对文件存在性和哈希；如发现差异，先判断是否为已有修改并暂缓关联删除。不得重写基准来消除差异。
3. 必要时运行小范围运行验证：解释器及原生扩展加载、模型配置、样例读取、界面创建与关闭。仅在风险或用户要求需要时重跑真实端到端任务，不把文件哈希或界面启动描述为完整功能验证。
4. 临时验证使用隔离状态目录，避免改写用户配置、交付文件或旧验收证据。关闭日志句柄、窗口和子进程后清理临时文件；应用保持日志句柄时，可在验证进程退出后由外部清理。

长时间哈希校验使用分块读取和定期进度，最后汇总总数、缺失数和不匹配数。读取进度本身不是通过证据；工具尚未返回最终结果时，不宣称零错误。合理间隔等待，避免频繁空轮询。

如果用户要求复核已经执行的清理，应明确哪些项已删，再检查剩余依赖与交付物；不要把事后验证描述成删除前验证。发现误删依赖时优先从可信保留副本或可重建来源恢复。

## 执行清理并复查

- 在授权范围内，验证通过后只删除精确清单中的已确认项。可疑项保留不阻塞其余安全项。
- Windows 递归删除前解析并检查每个绝对路径，确保处于指定工作区边界内且不等于工作区根目录。检查目标和父目录中的符号链接、目录联接及其他重解析点；不要递归穿过边界不明的链接。
- 同一个 shell 完成路径检查和删除；PowerShell 使用 `Remove-Item -LiteralPath`。不要把 PowerShell 枚举结果交给 `cmd /c` 或拼接成另一 shell 的删除命令，也不要使用宽泛通配符批量删除。
- 删除前累计目标文件大小；遇到删除失败、占用或部分完成，记录实际结果，不把计划删除量算成已释放量。逻辑文件大小不等同于物理磁盘回收空间，报告时使用“约删除 X GiB 文件”等准确表述。
- 删除后确认目标状态、必要保留项及 Git 状态与初始基线一致。只在删除影响或新异常需要时追加验证，不反复运行已通过的完整检查。

## 交付结果

简要说明实际删除范围和约计大小、因依赖保留的主要目录、验证结果与未覆盖范围、是否仍有失败或待处理项。区分“代码未修改”“哈希匹配”“运行加载通过”和“真实业务流程通过”。

本流程本身不要求写入仓库报告。用户需要档案时再保存明确路径的清理记录；不要为清理任务制造不必要的新文件。
