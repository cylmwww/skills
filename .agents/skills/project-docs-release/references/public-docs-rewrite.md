# 公开文档改写流程

把项目介绍与使用文档整理成第一次接触项目的人能理解、定位入口并运行的说明。按本次任务选用必要步骤，不把流程变成固定问卷。

## 先确定改什么

读取仓库适用的 AGENTS.md、Git 状态、README、文档列表与忽略规则。区分用户原有改动与本次工作，并识别已有提交/推送授权。后续补充默认延续当前任务；用户撤回忽略或删除要求后，停止该操作。

文档任务与功能实施分开处理。用户只要求改文档，不因此修改业务代码、删除测试或重新部署；用户另行要求这些操作时按对应范围执行。用户说“git 当前版本”时说明提交包含哪些现有改动；仅提交文档时精确限定路径。对“那个文件”先尝试从仓库唯一定位，无法可靠确定目标时简短询问，同时继续不依赖答案的工作。

## 从源码确认当前用法

优先查看应用入口与路由、CLI 参数、启动编排、环境模板、配置预设、数据契约，以及相关模块的实际调用。旧 README 和历史报告用于发现待核对点，不能作为当前能力的唯一依据。

尤其核对：

- 初始化是否已自动迁移、校验和入库，避免让读者重复构建索引。
- 默认功能与需要显式开启的增强，页面配置与环境配置的实际生效方式。
- 页面、API、CLI 是否走同一执行路径；单轮问答、多轮任务与可选循环应分别描述。
- 模拟数据、模拟模型、真实供应商调用、业务审批及到账分别是什么。
- 现有证据证明的是程序机制、真实技术执行还是人工业务正确性；无法确认的效果不写成已验收。

机器读取的 manifest、Schema、配置 ID、包名和数据状态不是文章。通过说明文档解释其含义，不为消除“阶段感”修改机器契约或有效启动命令。

## 改写内容

README 让新读者依次理解项目目的、适用场景、主要功能、使用入口、快速启动与能力边界。按项目规模补充代码架构，解释主要模块职责、核心调用链和持久化边界；只列真实存在的模块。

使用文档按主题回答操作问题，例如环境安装、索引管理、检索与重排、生成配置、业务会话、证据审核。保留必要示例、失败处理和限制；去掉开发批次、阶段计划、版本修复流水、逐轮测试成绩、个人审批对话及内部档案入口。

“去掉开发内容”不是删除源码或抹除能力边界。保留用户运行需要的配置名、模型模式区别、权限限制、恢复条件和失败行为。历史结果不冒充本轮验证，在线审核通过不等于业务语义正确。

公共使用文档应独立可用，不依赖被忽略的私有数据库、个人目录、真实密钥或本地验收报告。用户要求保留 changelog 时，它可以继续承担版本记录职责；不要把其流水重新复制回使用说明。

## 按用途命名并同步引用

新文档使用主题名称；用户要求整理现有名称时，先列出旧名到新名的映射并检查重名冲突。例如 `setup.md`、`workbench.md`、`index-management.md`、`retrieval.md`、`answer-configuration.md`、`agent-and-sessions.md`、`evidence-review.md`、`data-validation.md`。这是示例，不是每个项目必须建立的目录模板。

重命名前搜索整个相关仓库的文件名引用，覆盖 README、公开文档、代码、脚本和构建配置；必要时检查精确指定的本地材料。检查真实调用方，不能仅依据文件名认定没有依赖。正常资料已经按用途命名时保留原名。

使用同一映射更新相对链接及文本路径，保留仍然有效的锚点。若改变标题，连同指向该标题的锚点一起核对。只要求重命名时，确认内容差异仅来自文件名引用；不能顺手修改已接受的正文或数据。

## 用户要求本地保留时

仅针对已明确指定的文件或目录添加精确忽略规则，例如 `/docs/changelog.md`。不要用 `/docs/` 隐藏全部使用文档，也不要从“忽略版本记录”推导出忽略评测脚本或评测数据。

已跟踪文件需要 `git rm --cached -- <精确路径>`；新增忽略规则本身不会停止跟踪。操作前确认没有需要保留的独立暂存改动，并记录本地文件内容，之后确认文件存在且内容保持、`git ls-files` 已不包含目标、`git check-ignore` 命中预期规则。取消跟踪不会清除历史。

公开 README 与使用文档不得链接到取消跟踪后新读者无法取得的文件；保留已授权的本地内容，不擅自删除归档。用户要求忽略的文件仍被代码、测试或构建引用时，先明确依赖影响，再在授权范围内解决；不能让新拉取的仓库因缺少本地文件而失败。

## 验证与交付

验证与实际改动匹配，优先使用仓库已有工具。必要时做一次性只读检查，不为文档任务新增测试框架。

- 验证相对链接、文件存在和标题锚点；重命名后搜索残留旧文件名，区分历史文字、有效代码契约与失效引用。
- 对照实际 CLI 参数、环境变量、预设文件和配置组合；存在配置校验器时可在无真实凭证条件下验证示例，未单独授权时，不执行会入库、删除数据或付费的命令来“验证文档”。
- 仅在内容关联时运行离线数据检查、构建或其他必要门禁。参数和链接检查不等于已启动服务或完成真实模型验收。
- 检查数据、业务代码、原有用户改动及本次排除项是否保持预期；本地保留文件仍存在且未误暂存。
- 用户授权提交时，精确暂存并检查 `git diff --cached --name-only`、`git diff --cached` 与 `git diff --cached --check`，再提交；推送另按授权。避免未经检查的全量暂存。

交付说明给出主要文档入口、重命名和忽略结果、完成的验证及未完成项；执行了 Git 操作时分别报告提交哈希、工作区状态和推送状态。无需复述全部工具步骤。
